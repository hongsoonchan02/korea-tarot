# Backend Verification Checklist: AI Tarot Application

**Purpose**: 백엔드 API 서비스 배포 전 기획 명세서의 정책 가이드라인 및 기술 헌장 규칙에 충족하는지 무결성을 최종 검증하는 마스터 체크리스트입니다.  
**Feature**: `/specs/tarot/backend/spec.md`

---

## 1. 회원 가입 및 인증/인가 제어 (Auth & Security Control)

- [ ] **CHK-BE-001** 외부 가입 및 인증 API(`POST /api/v1/auth/signup`, `POST /api/v1/auth/login`) 호출 시, 패스워드가 평문이 아닌 안전한 단방향 암호화 서식으로 디바이스 데이터베이스에 영속화되는가? (태스크 연동: `T007`, `T008`)
- [ ] **CHK-BE-002** 요청 헤더에 JWT 토큰을 누락시키거나 임의 변조한 불량 패킷을 `/api/v1/tarot/**` 경로로 인입 시, 비즈니스 코어 스레드에 닿지 않고 Spring Security 최전방 가드 단에서 `401 Unauthorized` 코드로 명확히 튕겨내는가? (태스크 연동: `T010`)
- [ ] **CHK-BE-003** 전송된 JWT 토큰 내부 Claims 데이터 구조로부터 타겟 유저의 고유 식별 PK 값인 `user_id`를 디코딩 과정에서 누락 없이 무결하게 추출해낼 수 있는가? (태스크 연동: `T004`)

---

## 2. 고민 유효성 및 자원 보호 가드 (Validation & Rate Limit Guard)

- [ ] **CHK-BE-004** 동일한 유저 토큰 권한 사양으로 1분 주기에 이미 3회의 정상 상담을 마감한 상태에서 4번째 생성 API를 연속 청구 시, Redis 카운터 가드를 통해 비즈니스 스레드를 차단하고 즉각 `429 Too Many Requests` 상태 코드를 반환하는가? (태스크 연동: `T019`)
- [ ] **CHK-BE-005** 사용자가 고민 본문에 공백(Space) 및 줄바꿈(Enter)만 연속 입력하여 의도적으로 10자 벽을 우회하려고 시도할 때, 스프링 validation 레이어가 이를 포착하여 `400 Bad Request` 유효성 예외 응답을 출력하는가? (태스크 연동: `T015`)
- [ ] **CHK-BE-006** 유저 인입 고민 텍스트 본문에 시스템 내부 프롬프트 초기화를 명령하여 LLM을 교란하려는 악성 인젝션 문구(`ignore previous instructions` 등) 주입 시, `PromptShield` 내부 정규식에 걸려 차단 모듈이 정상 동작하는가? (태스크 연동: `T015`)

---

## 3. 트랜잭션 격리 및 외부 AI 장애 대응 (Resilience & Fail-Safe)

- [ ] **CHK-BE-007** AI 추론 외부 서버 진입 구간에서 지연이 발생할 때, 전체 임계 타임아웃 15초 바운더리 내에서 1회 재시도 정책을 정상 소화하기 위해 개별 시도당 ReadTimeout이 `7000ms`로 쪼개어 엄격히 작동하는가? (태스크 연동: `T016`, `T020`)
- [ ] **CHK-BE-008** AI 허브 서버가 완전히 다운되어 최종 타임아웃 15초를 돌파했을 때, 기존 데이터베이스 커밋 전체를 롤백(Rollback)하는 대신 익셉션을 가로채어 상담 레코드 상태 필드를 `status = FAIL`로 안전하게 영속 마감하는가? (태스크 연동: `T021`)
- [ ] **CHK-BE-009** 상기 AI 네트워크 단절 및 통신 실패 상황에 처한 사용자 유저 패킷에게 시스템 블랙아웃 대신 글로벌 익셉션 핸들러를 경유하여 최종 정제 포맷의 `503 Service Unavailable` JSON 응답을 일관되게 반환하는가? (태스크 연동: `T011`, `T022`)

---

## 4. 데이터 수명 주기 및 이력 페이징 (Data Lifecycle & Pagination)

- [ ] **CHK-BE-010** 마이페이지 이력 페이징 목록 API(`GET /api/v1/tarot/readings`) 호출 시, 하이버네이트 `@SQLRestriction` 글로벌 조건 가드가 정상 주입되어 `deleted_at` 필드가 **NULL**인 정상 활성 항목들만 자동 필터링되어 출력되는가? (태스크 연동: `T023`, `T024`)
- [ ] **CHK-BE-011** 반환되는 이력 리스트 응답 규격이 기획 명세 가이드라인에 부합하게 상담 시점 날짜, 20자 마크다운 요약 스트링 본문, 선택한 카드 ID 콤마 결합 포맷과 상태값을 온전히 리턴 구조화하고 있는가? (태스크 연동: `T014`, `T024`)
- [ ] **CHK-BE-012** 사용자가 이력 내 특정 항목을 지정하여 삭제(`/api/v1/tarot/readings/{id}`)를 감행 시, 물리적인 데이터 Row 행이 날아가지 않고 `deleted_at` 컬럼에 실행 기점의 실시간 타임스탬프 일시가 기록(Soft Delete)되는가? (태스크 연동: `T025`, `T026`)
- [ ] **CHK-BE-013** 인가 권한이 없는 타인의 인증 토큰 정보 혹은 비정상적인 변조 ID 값을 조작 기입하여 타인의 타로 이력 데이터 행 삭제를 유도 시, 소유권 확인 레이어가 작동하여 권한 거부 예외를 던지는가? (태스크 연동: `T025`)

## 5. 아키텍처 성능 및 시스템 품질 (Architecture Specs & Observability)

- [ ] **CHK-BE-014** `build.gradle` 스크립트에 명시된 Spring Boot 3.x, Java 21, 롬복, JWT 라이브러리 간의 버전 간섭 충돌 없이 Gradle 데몬 컴파일 및 컴포넌트 스캔 과정이 무결하게 마감되는가? (태스크 연동: `T001`, `T003`)
- [ ] **CHK-BE-015** 모든 클라이언트 API 인입 및 통신 트랙 전체에 `MDC(Mapped Diagnostic Context)` 레이어가 개설되어 파일 시스템에 적재되는 구조화 로그 내부에 동일한 고유 `Request ID(UUID)`가 추적 라벨링되는가? (태스크 연동: `T012`, `T029`)
- [ ] **CHK-BE-016** 대량 데이터 누적 환경을 가정하여 복합 인덱스(`user_id`, `created_at`)를 MySQL 테이블에 정상 포워드 적용 시, 마이페이지 페이징 서칭 쿼리 속도가 CPU 과부하 없이 성능 목표치인 **10ms 미만**을 기록하는가? (태스크 연동: `T027`)
- [ ] **CHK-BE-017** 독립 가상 장애 주입 환경 도구인 `MockWebServer` 통합 테스트 코드를 구동했을 때, 설계해 둔 비동기 WebClient 예외 복구 시나리오가 에러 없이 백퍼센트 그린 라이트 통과(Pass)를 마크하는가? (태스크 연동: `T028`)
